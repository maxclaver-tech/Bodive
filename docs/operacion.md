# Manual de operación

## Preparar las cuentas y el presupuesto

1. Sube el repositorio a GitHub, preferiblemente privado, y protege su rama por defecto y el entorno `bodive`. Limita quién puede modificar los workflows o acceder a sus secretos.
2. En Supabase aplica [la migración](../supabase/migrations/202611270001_bodive.sql) con el SQL Editor o el gestor de migraciones. Conéctate como administrador desde `psql` y ejecuta `CREATE ROLE bodive_worker LOGIN IN ROLE bodive_runner;`, seguido de `\password bodive_worker` para establecer la contraseña interactivamente. Copia el host del **Session pooler**, usa el usuario `bodive_worker.<project-ref>` y codifica la contraseña para URI cuando proceda. Descarga el certificado CA de Supabase. El cliente exige `sslmode=verify-full`. [Conexión a Postgres de Supabase](https://supabase.com/docs/guides/database/connecting-to-postgres)
3. Crea un bot dedicado con BotFather. Abre una conversación privada y envíale `/start`. Obtén tu ID numérico del campo `message.from.id` de `getUpdates` con una petición segura fuera de este repositorio. Usa el mismo ID como chat privado y operador. Mantén un solo consumidor de `getUpdates` y el bot sin webhook. [Telegram Bot API](https://core.telegram.org/bots/api#getupdates)
4. Si vas a utilizar Claude, crea una clave dedicada en un workspace con tope de gasto. Verifica la tarifa vigente y el coste máximo en EUR con impuestos y conversión. Controla también la recarga automática y cualquier cargo de infraestructura. Los cargos ajenos a BODIVE, incluidos GitHub Actions y el plan de Supabase, quedan fuera de su control transaccional. Opera dentro de cuotas sin cobro o autoriza y registra esos costes dentro de los mismos 100 EUR antes de activar el servicio. [Workspaces de Claude](https://platform.claude.com/docs/en/manage-claude/workspaces) · [Precios de Claude](https://platform.claude.com/docs/en/about-claude/pricing) · [Límites de GitHub Actions](https://docs.github.com/en/actions/reference/limits)
5. En el entorno de GitHub `bodive`, añade como secretos `SUPABASE_DATABASE_URL`, `SUPABASE_CA_CERT` (PEM completo), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OPERATOR_ID` y, para generación, `ANTHROPIC_API_KEY`. Configura como variables `CLAUDE_MODEL`, `CLAUDE_INPUT_CENTS_PER_MILLION` y `CLAUDE_OUTPUT_CENTS_PER_MILLION`. Los modelos admitidos son `claude-haiku-4-5-20251001` (mínimos locales 200/1000) y `claude-sonnet-4-6` (600/3000). Introduce límites conservadores que cubran tu coste máximo, en céntimos de euro por millón de tokens. [Secretos de Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)
6. Ejecuta primero **BODIVE → demo**. Para habilitar producción añade la **variable de repositorio** `BODIVE_LIVE_ENABLED=yes`. Ejecuta `report` para probar Supabase y `poll` para procesar Telegram. El sondeo programado es horario y puede retrasarse. También puedes lanzarlo manualmente. En local, instala `pip install '.[cloud]'`, exporta las variables necesarias y fija `PGSSLROOTCERT` con la ruta al PEM, `BODIVE_MODE=live` y `BODIVE_LIVE_ENABLED=yes`.

## De un tema a un producto

1. Ejecuta `plan` con un tema en inglés. Usa `/dossier ID` en el bot o `bodive show ID` en local. Revisa las fuentes, valida demanda y competencia por cuenta propia y ajusta las hipótesis si procede. La CLI acepta `--price`, `--unit-cost` y `--fixed-cost` en céntimos de euro. Actions usa 1200/400/0 como escenario inicial.
2. Si quieres un borrador con Claude, ejecuta `propose-claude DOSIER`. Ejecuta `notify APROBACION` y envía los comandos de revisión y decisión que devuelve Telegram. Tras procesar la aprobación con `poll`, ejecuta `run-claude APROBACION`. Consulta el borrador con `/result APROBACION`. Revisa la factura antes de registrar el coste en céntimos mediante `complete APROBACION CENTIMOS REFERENCIA`. Una llamada incierta conserva su reserva y su cuota. Inspecciona el proveedor antes de conciliarla o pedir una nueva autorización.
3. Ejecuta `propose-publish DOSIER`. Para adjuntar un borrador de Claude ya conciliado, usa `--draft-id APROBACION` en la CLI o el campo `draft_id` de Actions. Envía `notify`, revisa el paquete con `/review ID` y aprueba su versión exacta. Antes de aprobar, verifica el contenido, la originalidad y los derechos, la descripción, el precio y la divisa.
4. Envía `/claim ID` para tomar la tarea manual y `/ready ID` inmediatamente antes de actuar. En el panel de Gumroad crea el producto digital, introduce la ficha aprobada, guarda el contenido Markdown como `workbook.md`, sube el archivo y publica si el panel coincide con lo autorizado. Registra la URL con `complete ID 0 https://...`. Si el panel exige un cargo o cambia el alcance, solicita otra autorización. [Guía de publicación en Gumroad](https://gumroad.com/help/article/357-sell-an-ebook)
5. Para anuncios o gastos externos, usa `propose-manual advertise|expense CENTIMOS DESCRIPCION`. Especifica alcance, proveedor o canal, y en su caso el texto público y la duración. Usa el mismo flujo de aprobación, toma de tarea y comprobación, fija el tope con el proveedor y asienta el cargo comprobado. Para un cobro ya liquidado, usa `income CENTIMOS REFERENCIA` con el importe neto realmente recibido en EUR y un identificador único, sin datos de clientes. El saldo de presupuesto no se incrementa con ingresos.

## Controles y recuperación

- Las aprobaciones vencen a las 24 horas y solo se pueden tomar una vez. El identificador y el hash vinculan tipo, importe y contenido. PostgreSQL serializa los cambios de saldo. El límite acumulado para compromisos más gastos liquidados es **100 EUR**. El importe autorizado queda reservado hasta verificar el coste real o confirmar que no existió ningún cargo.
- Para Claude, el cliente valida hasta 4.000 tokens de entrada vía conteo, limita la salida a 1.600 y reserva la tarifa conservadora de hasta un millón de tokens de entrada más la salida. Acepta hasta tres intentos al día UTC y veinte de por vida de esa base. No repite llamadas facturables automáticamente. GitHub Search admite hasta doce consultas diarias desde cada base. [Claude Messages](https://platform.claude.com/docs/en/api/messages) · [Conteo de tokens](https://platform.claude.com/docs/en/build-with-claude/token-counting) · [GitHub REST Search](https://docs.github.com/en/rest/search/search)
- Envía `/stop` y ejecuta `poll`, o ejecuta `bodive stop` desde una estación configurada para aplicar la parada sin esperar a Actions. Bloquea nuevas operaciones, cancela las pendientes o aprobadas e invalida reclamaciones abiertas conservando su reserva. Una llamada ya enviada o una acción humana fuera de BODIVE se comprueba y, si corresponde, se cancela en el proveedor. Ante una urgencia, cancela el workflow en curso y suspende el acceso o gasto en el proveedor. Reactiva deliberadamente con `resume` tras revisar `events` y `report`.
- Si se pierde la respuesta de Telegram al tomar una tarea, comprueba `/review ID`, `/ready ID` y el panel del proveedor antes de actuar. Si confirmas que no hubo publicación ni cargo, reconcilia a cero con una referencia `void:motivo`. Si el gasto excede un límite autorizado, detén la operación y reconcilia la discrepancia externamente antes de volver a habilitarla.
- La API pública de Gumroad se revisó junto a su documentación de producto. El flujo implementado usa el panel para crear el producto, subir el archivo y publicarlo. Esta versión prescinde de un token de Gumroad y del procesamiento de webhooks. [API de Gumroad](https://gumroad.com/api) · [Panel de producto](https://gumroad.com/help/article/357-sell-an-ebook)
